# Tanda 11 — Plan de implementación

> **Para quien lo ejecute:** usar `superpowers:subagent-driven-development` (recomendado) o
> `superpowers:executing-plans`. Los pasos van con checkbox (`- [ ]`) para ir tildando.

**Objetivo:** cerrar el ciclo de vida de un reporte (que la app pregunte si apareció), dejar que el
vecino que encuentra un animal avise **sin cuenta**, mostrar los avisos **dentro** de la app, y
emparejar adopción con el resto del producto.

**Arquitectura:** cuatro piezas independientes que comparten dos patrones ya probados en el repo: RPC
`security definer` **sin parámetros de identidad** (el usuario sale de `auth.uid()`, nunca de un
argumento) para todo lo que lee datos propios, y RPC `security definer` con `grant … to anon` +
rate-limit para lo que escribe un anónimo. Ninguna pieza toca las Edge Functions, así que **no hay
redeploy de funciones** en esta tanda.

**Stack:** Expo/React Native + react-native-web, TypeScript, Supabase (Postgres + RLS + PostgREST),
jest + react-test-renderer.

## Restricciones globales

  Todo lo nuevo degrada: la sección no aparece o muestra su estado de error, y **nada de lo que ya

```ts
// src/lib/cierreCasos.ts
// Los hitos salen de las medianas medidas de recuperación: 2 días en perros y
// 5 en gatos. A los 3 días la mayoría ya se resolvió; a los 21, un reporte que
// sigue abierto casi siempre es un aviso zombi que nadie cerró.
export const HITOS = [3, 7, 21] as const;
export type Hito = (typeof HITOS)[number];

export function debePreguntar(
  r: { creado_en: string; activo: boolean; reunida_en: string | null; preguntado_en: string | null },
  ahora: Date,
): { preguntar: boolean; hito: Hito | null } {
  if (!r.activo || r.reunida_en) return { preguntar: false, hito: null };
  const dias = (t: string) => (ahora.getTime() - Date.parse(t)) / 86400000;
  const transcurridos = dias(r.creado_en);
  const alcanzados = HITOS.filter((h) => transcurridos >= h);
  if (alcanzados.length === 0) return { preguntar: false, hito: null };
  const ultimo = alcanzados[alcanzados.length - 1];
  // Ya se le preguntó DESPUÉS de alcanzar este hito: no repetir.
  if (r.preguntado_en && dias(r.preguntado_en) <= transcurridos - ultimo) {
    return { preguntar: false, hito: null };
  }
  return { preguntar: true, hito: ultimo };
}
```

```sql
-- 00XX_cierre_casos.sql — que la app pueda preguntar "¿apareció?".
--
-- Aditiva: dos columnas nullable y una RPC. Sin ellas la app funciona igual
-- (la tarjeta simplemente no se muestra, ver el cliente).
alter table public.pets add column if not exists preguntado_en timestamptz;
alter table public.pets add column if not exists cierre_motivo text
  check (cierre_motivo is null or cierre_motivo in ('aparecio', 'sigo_buscando', 'ya_no_busco'));

-- Sin parámetro de usuario a propósito: el dueño sale de auth.uid(), nunca de
-- un argumento. Es el mismo patrón de `mi_perfil()` y `anonimizar_mi_cuenta()`,
-- que ya evitó una escalada de privilegios en este repo.
create or replace function public.responder_estado(p_pet_id uuid, p_respuesta text)
returns void
language plpgsql security definer set search_path = public, pg_temp
as $$
begin
  if p_respuesta not in ('aparecio', 'sigo_buscando', 'ya_no_busco') then
    raise exception 'respuesta invalida';
  end if;

  update public.pets
     set preguntado_en = now(),
         cierre_motivo = p_respuesta,
         -- "Apareció" cierra el reporte Y registra el reencuentro: si solo
         -- pusiera activo=false, no sumaría al contador de Inicio ni a la
         -- galería, que es exactamente el bug que se arregló en la tanda 9.
         reunida_en = case when p_respuesta = 'aparecio' then coalesce(reunida_en, now()) else reunida_en end,
         activo = case when p_respuesta = 'sigo_buscando' then activo else false end,
         -- "Sigo buscando" RENUEVA: la persona confirmó que sigue vigente.
         renovado_en = case when p_respuesta = 'sigo_buscando' then now() else renovado_en end
   where id = p_pet_id and user_id = auth.uid();

  -- Sin esto, responder sobre un reporte ajeno o inexistente devolvería éxito
  -- habiendo hecho cero. Es la forma del bug de la 0017.
  if not found then
    raise exception 'no se pudo registrar la respuesta';
  end if;
end;
$$;
revoke all on function public.responder_estado(uuid, text) from public, anon;
grant execute on function public.responder_estado(uuid, text) to authenticated;
```

`avisar_escaneo_collar` (0027) es el patrón probado: `security definer`, `grant … to anon`,
rate-limit por ficha, y **no delata existencia** (si el reporte no existe, retorna sin error).

```sql
-- 00XX_aviso_anonimo.sql
create or replace function public.avistar_sin_cuenta(
  p_pet_id uuid,
  p_nota text default null,
  p_lat double precision default null,
  p_lng double precision default null
)
returns void
language plpgsql security definer set search_path = public, pg_temp
as $$
declare
  v_pet public.pets%rowtype;
begin
  select * into v_pet from public.pets where id = p_pet_id and activo = true;
  -- No delatamos si existe o no: mismo criterio de privacidad que el collar.
  if not found then return; end if;

  -- Rate-limit por reporte, igual que el collar: evita martillar el botón.
  if exists (
    select 1 from public.notification_events ne
    where ne.tipo = 'avistamiento_anonimo'
      and ne.pet_id = p_pet_id
      and ne.creado_en > now() - interval '5 minutes'
  ) then
    return;
  end if;

  insert into public.notification_events (tipo, pet_id, target_user_id, actor_id, datos)
  values ('avistamiento_anonimo', p_pet_id, v_pet.user_id, null,
          jsonb_build_object('nota', left(coalesce(p_nota, ''), 500),
                             'lat', p_lat, 'lng', p_lng));
end;
$$;
revoke all on function public.avistar_sin_cuenta(uuid, text, double precision, double precision) from public;
grant execute on function public.avistar_sin_cuenta(uuid, text, double precision, double precision) to anon, authenticated;
```

⚠️ **`notification_events.tipo` tiene un CHECK.** Hay que ampliarlo en la misma migración para
aceptar `'avistamiento_anonimo'`, y **el dispatcher (`send-notifications`) tiene que saber
componerlo**. Si no se va a redesplegar la Edge Function en esta tanda, el evento quedaría encolado y
sin enviar: en ese caso, **la Tarea 3 (bandeja in-app) lo cubre**, porque ahí sí se ve. Dejarlo
escrito en el informe.

```sql
-- 00XX_mis_avisos.sql
-- Sin parámetros a propósito: el destinatario sale de auth.uid(). Si recibiera
-- un p_user_id, cualquiera leería la cola ajena — el mismo error que se evitó
-- en `mi_perfil()` y en `anonimizar_mi_cuenta()`.
create or replace function public.mis_avisos(p_limite int default 50)
returns table (id uuid, tipo text, pet_id uuid, datos jsonb, creado_en timestamptz)
language plpgsql security definer set search_path = public, pg_temp
as $$
begin
  if auth.uid() is null then
    raise exception 'no autorizado';
  end if;
  return query
    select ne.id, ne.tipo, ne.pet_id, ne.datos, ne.creado_en
      from public.notification_events ne
     where ne.target_user_id = auth.uid()
     order by ne.creado_en desc
     limit least(greatest(p_limite, 1), 200);
end;
$$;
revoke all on function public.mis_avisos(int) from public, anon;
grant execute on function public.mis_avisos(int) to authenticated;
```

⚠️ **Ojo con `target_user_id`:** no todos los eventos lo llenan. Los de `reporte_nuevo` van por zona
y se resuelven **en el dispatcher**, no en la fila. Esta bandeja muestra los **dirigidos**
(coincidencia, escaneo de collar, búsqueda guardada, avistamiento anónimo). **Decirlo en el informe y
no prometer que están todos.**
