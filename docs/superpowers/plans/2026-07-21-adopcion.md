# Apartado de Adopción — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development para cada tarea con lógica. Steps usan checkbox (`- [ ]`). Ejecutar tarea por tarea, en orden: la base (1–6) antes que la UI (7–12), porque el refactor del chat (tarea 6) es central y sus consumidores deben quedar compilando.

**Goal:** Un apartado dedicado de adopción con feed tipo Instagram (tabla propia, publicar, detalle, guardar, contactar por chat, final feliz), separado de los reportes.

**Architecture:** Tabla `adoptions` nueva + RPC `buscar_adopciones` (cursor). Chat generalizado (`messages` suma `adoption_id`; `messages.ts` pasa a un contexto de hilo explícito `HiloCtx`). Guardar con tabla paralela `adoption_saves`. Pantallas nuevas + 8ª pestaña.

**Tech Stack:** Expo (RN+TS, web), Supabase (Postgres/RLS/PostGIS), jest, zod.

## Global Constraints

- **Spec = fuente de verdad del diseño:** `docs/superpowers/specs/2026-07-21-adopcion-design.md`
  (tiene el esquema de la tabla, la trampa del chat y las firmas **verbatim**). Este plan da
  el orden; el detalle técnico está en el spec.
- **Migración asignada: `0030`** (la última existente es `0029`).
- **`buscar_adopciones` conserva el arreglo del cursor de distancia de la 0015** (redondeo a
  numeric en el cálculo Y en la comparación del cursor).
- **`messages.pet_id` YA es nullable (0017).** El refactor debe evitar que
  `.is('pet_id', null)` (hilo de reporte borrado) matchee mensajes de adopción → contexto de
  hilo **explícito** (`HiloCtx`).
- **Ubicación difuminada** (`difuminarUbicacion`) al escribir; nunca la exacta.
- **`moderarTexto`** en publicar Y editar adopción (anti-bypass).
- Antes de cada commit: `npx tsc --noEmit` limpio y `npm test` verde.
- Copy cálido, español chileno; componentes de `src/ui`.
- Commits chicos; terminar cada uno con
  `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`.

## Task 1: Migración 0030 (fundación completa)

**Files:** Create `supabase/migrations/0030_adopciones.sql`

**Interfaces (Produces):** tabla `adoptions`, `messages.adoption_id`, tabla `adoption_saves`,
RPC `buscar_adopciones(p_especie text, p_tamano text, p_lat float8, p_lng float8, p_radio_km
float8, p_orden text, p_cursor_fecha timestamptz, p_cursor_id uuid, p_cursor_dist float8,
p_limite int)`.

- [ ] Escribir el SQL siguiendo el spec §"Migración 0030": tabla `adoptions` (con CHECKs de
  tri-estado, longitudes y cantidad de fotos; columna `ubicacion` geography generada + índice
  GIST; índice parcial de activas recientes), RLS (select público, insert/update/delete del
  dueño); `alter table messages add column adoption_id uuid references adoptions(id) on delete
  set null` + índice; tabla `adoption_saves` (pk (user_id, adoption_id), RLS del dueño); RPC
  `buscar_adopciones` (security invoker, cursor con redondeo numeric, excluye
  inactivas/ocultas/adoptadas; **SIN filtro de bloqueo en la RPC** — `buscar_reportes` tampoco
  lo hace y `hay_bloqueo_con` es solo para authenticated mientras el feed es público);
  **ampliar el CHECK de `denuncias.tipo` (0025) con `'adopcion'`** (drop + add defensivo).
- [ ] Revisión de sintaxis por lectura (no se aplica a prod acá). Commit.
